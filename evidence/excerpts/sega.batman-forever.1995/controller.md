# Batman Forever controller routing

Pinned authority: PinMAME `97aa922bf8e4b6970126192ec1ac1fb0305a4f62`. Direct source read by the primary curator. These are factual extracts of the named symbols at that revision.

- `degames.c` 1532-1843: the Batman Forever block. Every driver is "CPU Rev 3b / DMD Type 3 2x512K Rom - 64K CPU Rom". Line 1535: `INITGAMES11(batmanf, GEN_DEDMD64, de_192x64DMD, FLIP6364, SNDBRD_DE2S, SNDBRD_DEDMD64, S11_PRINTERLINE)`. Line 1543: `#define input_ports_batmanf input_ports_des112`. Every clone defines `init_<clone>` as `init_batmanf` and `input_ports_<clone>` as `input_ports_batmanf`, and is declared with `CORE_CLONEDEFNV(<clone>,batmanf,...,"Sega",de_mDEDMD64S2A,0)`.
- Drivers and descriptions: `batmanf` "Batman Forever (4.0)", `batmanf3` "(3.0)", `batmanf2` "(2.02)", `batmanf1` "(1.02)", `bmf_uk` "(4.0 English)", `bmf_cn` "(4.0 Canadian)", `bmf_no` "(4.0 Norwegian)", `bmf_sv` "(4.0 Swedish)", `bmf_at` "(4.0 Austrian)", `bmf_ch` "(4.0 Swiss)", `bmf_de` "(4.0 German)", `bmf_be` "(4.0 Belgian)", `bmf_fr` "(4.0 French)", `bmf_nl` "(4.0 Dutch)", `bmf_nl302` "(3.02 Dutch, Display 4.01)", `bmf_it` "(4.0 Italian, Display 4.01)", `bmf_it2` "(4.0 Italian, Display 4.0)", `bmf_it3` "(4.0 Italian, Display 4.0, Early sound)", `bmf_sp` "(4.0 Spanish)", `bmf_jp` "(4.0 Japanese)", `bmf_time` "(4.0 Timed Play)" (all year 1995), `batmanf5` "Batman Forever (5.0 unofficial MOD)" (2024) and `batmanf501` "(5.01 unofficial MOD)" (2025). They differ only in their CPU, display and sound ROM images.
- `degames.c` 77-80 `INITGAMES11`: `core_tGameData name##GameData = { gen, disptype, {flippers,0,0,0,sb,db,gs1}, NULL, {{0}},{10}}`, so no custom solenoid count, no `getSol`, no simulator data and `{10}` as the mux solenoid; line 83 `DE_INPUT_PORTS_START2(des112, 1) DE_INPUT_PORTS_END`; line 89 `#define FLIP6364 FLIP_SWNO(63,64)`. `s11.h` 82-86: `DE_INPUT_PORTS_START2` uses `DE_COMPORTS2`, whose Green service input is momentary.
- `gen.h`: GEN_DEDMD64 = `0x8000`, the Data East/Sega 3b family of the `pinmame.dataeast` controller profile, not Whitestar.
- `s11.c` `pia4b_w` / `pia4a_r`: a Data East matrix strobe selects only its first set bit, and `pia4a_r` returns `core_getSwCol(locals.swCol)` without complementing it. `core.c`'s default sequential conversion is n+7, so matrix numbers 1-64 are column-major (`(n-1)//8+1`, `(n-1)%8+1`).
- `s11.c` `setSSSol`: the Data East special-solenoid permutation is `{3,4,5,1,0,2}`; public 17-22 are the six special drivers.
- `s11.c` `updsol`: latch2200 drives 1-8 and PIA0:B drives 9-16; with the mux relay at public 10 on (`sxx.muxSol` 10), the low byte moves to 25-32. These are the PPB's alternate loads behind the K1 relay, not independent power stages. `pia0cb2_w` publishes the switched-solenoid enable at S11_GAMEONSOL = 23. No state producer exists at 24.
- `s11.c` `pia2b_w`: on GEN_DEDMD64 with S11_PRINTERLINE, `extSolPulse=data`; `core_getSol` publishes that byte at 37-44. The comment names bit 0 CN3 pin 9, bit 1 pin 8, bit 2 pin 7 and bit 7 pin 1; its literal `....` elides bits 3-6.
- `core.c` `core_updateSw`: without FLIP_SOL, the cabinet buttons in internal column 11 (public 82 right, 84 left) are copied to matrix 64 and 63 on every update, so a public write to 63/64 is overwritten. While the enable at 23 is on, 82 fabricates 45/46 and 84 fabricates 47/48. The other column bits (81, 83, 85-88) are neither copied nor synthesized.
- `core_getSol`: the Data East path publishes nothing at 33-36; 49 is a simulator shooter slot, 50 a gap, and 51+ need a custom count or `getSol`, which `INITGAMES11` does not declare. `pia2a_r` reads one country-jumper bit at `core_getDip(0)<<7`.
- `s11.c` 1252-1257, "DataEast/Sega 3b" PWM branch: a `strncasecmp(gn, "batmanf", 7)` prefix match (shared with `baywatch` and `mav_`) types output 11 as `CORE_MODOUT_BULB_44_6_3V_AC_REV` "GI output" and the eight muxed outputs 25-32 as `CORE_MODOUT_BULB_89_32V_DC_S11` "(K1 relay is solenoid #10)". This is the emulator's brightness model; it does not describe the per-socket #89/#906 mix the manual prints. The `bmf_*` clones do not match the `batmanf` prefix, so this branch applies to `batmanf`, `batmanf1`, `batmanf2`, `batmanf3`, `batmanf5` and `batmanf501` only.

## Runtime VPinMAME library

The retained table loads `LoadVPM "01560000","DE.VBS",3.1` (script line 136). Exact `de.vbs` SHA-256 `8858b4509a600f77a8a5844f138ed1c71f19b023550660efd62e308588e84d04`, "Last Updated in VBS v3.61", retained under `review-artifacts/vpm-script-libs`.

Constants (lines 20-36): GameOnSolenoid = 23; swBlack = -7; swGreen = -6; swTilt = 1; swBallRollTilt = 2; swStartButton = 3; swCoin1 = 4; swCoin2 = 5; swCoin3 = 6; swSlamTilt = 7; swLRFlip = 82; swLLFlip = 84; swURFlip = 86; swULFlip = 88. The generic BallRollTilt name at 2 is not this game's identity; the manual and ROM print 4TH COIN SLOT there.

`vpmKeyDown`/`vpmKeyUp` (lines 66-114) set 84 and 82 from the left and right flipper keys and call vpmFlips; the staged upper keys write 88/86 only while the matching `vpmFlips.FlipperSolNumber` is non-zero. Start writes 3, Black writes -7 while held, and Green toggles -6 (`.Switch(swGreen) = Not .Switch(swGreen)`), unlike the momentary des112 port. `core.vbs` (SHA-256 `a228644ec9714e32c5c6764254b151dc3ec9df2c438dd5a7ce9e9f324cc56f69`) defines `KeyDownHandler`/`KeyUpHandler` as `vpmKeyDown`/`vpmKeyUp` (lines 2854-2855) and the lower flipper callbacks sLRFlipper = 46 and sLLFlipper = 48.
