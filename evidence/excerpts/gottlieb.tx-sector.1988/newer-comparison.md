# TX-Sector newer VPX comparison

The newer SG1bsoN Mod v1.1 embedded script says **“Table not verified yet”** at line 39. Its static behavior is candidate runtime evidence, not a verified run or physical authority. The original manual supplies physical identity and quantity; the pinned PinMAME source supplies emulator metadata. The newer table is a community modification: no independent geometry ancestry is established. These observations do not justify author-ready promotion.

The neutral retained `derivations/newer-comparison/inputs/comparison.json` is the complete candidate mapping: source paths, verified object-file SHA-256, exact new script lines, raw object points, repository-helper normalized points, explicit old names/points, and each same-name/address delta. It includes all 50 active new `Lights()` assignments (not `vpmMapLights`), 30 playfield switch-address groups, all four hole-drive light sets, 41 GI/peg/apron render objects, ball release, and lower flippers. Off-plane/helper and unresolved points are kept as observations, not physical socket placements. Wall drag-point centroids are event-region approximations, not contact centers. Old bounds are (0,0)–(1000,2000); newer bounds are (0,0)–(952,1974). The same `pinmame_game_defs.spatial.extract_spatial_candidates` helper normalizes each from its own bounds, x left-to-right, y rear-to-apron. Vector differences below are newer minus older; distance is Euclidean normalized space. A same-named object does not guarantee the same physical part, especially when a lamp address binds several members.

## What the newer build adds

- **Switch 56:** `Kicker.sw56` is a new script-bound trough simulation object, raw (754.6307,1686.3547), normalized (0.792679,0.854283). Its Hit/UnHit sets/clears controller 56, and the trough timer moves it toward `ballrelease` (script lines 735–746). Old script uses a logical count and had no corresponding bound object. This closes a **table-geometry candidate** gap; neither this kicker center nor the 915064 underside mechanism was traced to the actual physical #2 contact, so the physical contact location remains unknown.
- **Outhole, release, holes:** `sw66` is a kicker at (0.512696,0.912982), controller 66 with solenoid 9 kick (lines 751–758); `ballrelease` is at (0.856171,0.841224), with lamp-2 activation in lines 1536–1549. Lines 596–598 create three simulated balls at sw66, sw56 and ballrelease; the number is a simulation fact. The four hole contacts are sw45 (0.126300,0.063806), sw55 (0.126470,0.145581), sw65 (0.826809,0.328839), and sw75 (0.736596,0.411702), with callbacks 1/2/5/6. Their centers are candidates or possible disclosed projections, not measured coil windings. Release delta versus old `BallRelease` is below 0.025; hole and outhole differences are listed below.
- **Shared 76:** new active handlers are sw76l, sw76r, sw76lt, sw76t, sw76rt (lines 1439–1443), all wall regions with vertices and centroids in JSON. The old script had seven candidates `LeftSlingShot`, `RightSlingShot`, `LminiKick`, `RminiKick`, `LBANKSW`, `TBANKSW`, `TR72SW`. These are not a demonstrated one-to-one mapping; no nearest match, averaging, or silent side swap has been applied. Extra sling animation handlers do not themselves pulse 76. Manual shared-contact topology remains the authority.
- **Lamp 29:** new `lights(29)=light29` (line 1494) still binds one Light, raw (434.5001,1012.4147), normalized (0.456408,0.512875), `show_bulb_mesh=false`; old L29 is (0.458500,0.489000), distance 0.023966. This is one insert/glow center, not the two physical holder axes. The prior underside photo 915063 and manual wiring substantiate two LOCK bulbs, but do not supply a calibrated newer-table socket pair. No second independently associated LOCK socket mesh was identified in the inspected bulb/socket primitives; generic or unnamed meshes have not all been exhaustively semantically identified.
- **Hole/flash multiplex:** lines 623–724 branch on public lamp-12 state: 1 turns on the flash render group; 0 kicks the corresponding hole. On disable, the `L12On`/`solact=115` condition can issue a delayed fallback kick; lines 1559–1586 update the transition timestamp. This is script tuning, not proof of real timing or physical relay polarity. All ten `lightsol1/1a/1b`, `lightsol2/2a/2pf`, `lightsol5/5a`, `lightsol6/6a` objects have `show_bulb_mesh=false`; most are broad-falloff lighting, and `lightsol1` is outside table bounds. Their raw coordinates and binding lines are retained, but none becomes a physical flash socket. The manual states two #67 bulbs on each multiplexed circuit; the photo pass could not trace all eight socket centers/circuits. The script's two or three visuals per callback do not settle that physical count or identity.
- **GI:** gion/gioff lines 471–588 switch GI render objects and optional PegLights. `GI_12` (0.184736,0.672666) and `GI_28` (0.725616,0.673214) show bulb meshes; the other named GI lights in this script do not. Of `PegLight001`–`021`, 002–021 have the flag and 001 does not; all 21 depend on the PegLights option. Those flags and options describe rendering and do not prove factory GI socket fitment, quantity, or identity. Their individual coordinates are candidate graphics only. The actual T-relay branch and source-photos wiring must establish each physical GI emitter. Virtual room/backglass/display options and animations (e.g. script lines 13–29, 51–54, 400–455 and display code after 1590) are table features, not new physical displays or devices.
- **Ramp mesh inspection:** `socket-mesh-inspection.json` and its reproducer actually read 16 named `Primitive.bulbsocket*.obj` meshes. Each listed primitive has zero rotations; local vertex bounds were transformed using its position and scale to obtain a world AABB midpoint, not by trusting stored origins. Fifteen transformed midpoints lie within 0.003 normalized of distinct bound 15–19 ramp lights; the manual independently lists 15 #86 ramp bulbs. This is useful correspondence evidence for the rendered ramp model, not an independent proof of every physical holder center or circuit. The sixteenth, `bulbsocket1`, is near (0.703304,0.727562) and has no established GI or LOCK identity. OBJ and primitive hashes, bounds, transformed center, and proximity records are retained. No dome/lens primitive named as such was found; the named mesh inspection does not exhaust all anonymously named geometry.
- **Other script changes:** old lamp 16 includes `L15C2`, already a lamp-15 helper; new lamp 16 instead uses the Light16 h-family and does not repeat that exact cross-address helper. The newer script assigns `lights(49)=light48` at line 1516, while the prior script had no active 49 assignment and its `Lights(48)` was commented. Object naming does not by itself settle the manual circuit identity.

## Reproduction and unresolved work

Portable scripts, retained inputs, exact SHA256 and relocation rules are indexed in [derivations.txt](derivations.txt). Set `$reviewRoot` to the review-artifacts root, `$work` to the retained working root, `$repo` to the repository and `$out` to a new output directory. With Python 3.13+, Pillow and repository dependencies (including jsonschema) available, run:

```powershell
python -B "$reviewRoot/gottlieb.tx-sector.1988/session-20261029/derivations/spatial/map_candidates.py" --working-root $work --repository-root $repo --photo-root "$reviewRoot/gottlieb.tx-sector.1988/session-20261029/parent-browser" --output-root "$out/spatial"
python -B "$reviewRoot/gottlieb.tx-sector.1988/session-20261029/derivations/newer-comparison/compare.py" --working-root $work --repository-root $repo --output-root "$out/newer-comparison"
python -B "$reviewRoot/gottlieb.tx-sector.1988/session-20261029/derivations/newer-comparison/inspect_socket_meshes.py" --working-root $work --output-root "$out/newer-comparison"
```

The spatial step writes `mapping.json`, `manual54-controls.json` and `manual54-checks.json`. Comparison reads the pinned neutral original mapping copy and writes `comparison.json`; mesh inspection reads that fresh comparison and writes `socket-mesh-inspection.json`. Existing expected output files are refused. All numerical values, object identities, deltas and mesh evidence reproduce exactly; descriptive source paths reflect supplied roots, and `source.old_mapping` now names the neutral retained mapping copy. Historical absolute paths inside byte-identical retained inputs remain descriptive provenance, not instructions to overwrite or open the original scratch locations. The extraction manifest and every new item JSON are checked, and mesh hashes are recorded. No VPX launch or ROM trace follows from this static derivation.
