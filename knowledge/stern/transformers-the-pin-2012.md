# Transformers The Pin (2012) recreation knowledge

`stern.transformers-the-pin.2012` is a partial physical-machine definition for exact root driver `tfcp_1018`. Exact firmware routes and a bounded fresh-state runtime are now retained. Physical wiring, fitment, mechanism topology, lamp semantics and geometry remain unresolved; it is not author ready.

## Identity and edition boundary

Own-edition OPDB `Grd2o-MQK8Z` records the physical 2012 home model, independently confirmed by IPDB 5861. Current API metadata names `Transformers The Pin (1.0.18)` with flags 0 and no clone parent. Sources `tfcp_1018.identity.opdb`, `tfcp_1018.identity.ipdb` and `tfcp_1018.catalog.api` establish this separate home product. Shared theme does not establish compatibility with commercial editions. Source `tfcp_1018.identity.stern`, the official October 1, 2012 release, names real flippers, slingshots, pops, traditional plunger and all-LED lighting but supplies no electrical map or geometry.

## Exact source and firmware route evidence

Sources `tfcp_1018.source.driver`, `tfcp_1018.source.devices` and `tfcp_1018.source.core` pin clean revision `46e1a01a0f73dc5ce163d98db1ae435883ecc450`, full-file hashes and numbered portable excerpts. `tfcp_1018.rom.map` binds the exact executable to the complete accepted ELG tables: 46 switches, 8 coils and 64 LED routes, all node 8. The portable map preserves public addresses, firmware node/position, source names, firmware wire-level flags, startup closure decisions, table regions and extractor/source/program hashes. ELF BSS is zero initialized as in the loader; all g_smap regions are inspected. The current standalone loader independently returns the same complete route list from this exact program. These are emulator routes, not physical device counts.

Actual firmware coil labels in public order are 1 SLINGSHOTS, 2 LEFT FLIPPER, 3 RIGHT FLIPPER, 4 TROUGH EJECT, 5 RIGHT RAMP BALL LOCK, 6 POP BUMPER - BOTTOM & RIGHT, 7 POP BUMPER - TOP and 8 DROP TARGET RESET. Combined labels do not prove how many physical devices share a channel. Blank-name and invalid raw coil rows are excluded by the source; public coil slots 9-32 and custom 51-72 have no exported route and are virtual unused. Output 33 is derived GAME ON; 45-48 are virtual lower-flipper mirrors. Duplicate direct aliases 34-36 are not extra canonical outputs.

Switches 1-46 have actual normalized firmware names. Public EOS 4/5 are synthesized by core after CORE_FLIPSTROKETIME; host writes are overwritten. Buttons 2/3 and tilt 46 agree with the exact initializer. Named trough routes 26/27/28 start closed because the loader explicitly initializes numbered TROUGH rows; their `initial_active` values record that emulator startup, not a physically proven ball count, opto part or contact construction. Firmware active_high/inverted flags are wire-level protocol facts and do not supply physical normally_closed. No polarity construction is inferred. Other admitted switch positions without an exact map route are virtual unused, except DIP readbacks 101-108, rewritten from bank 0 every millisecond. Configuration ordinals 1-8 are distinct from those mirrors. No CPU g_smap_gpio service inputs are exported.

Every lamp 1-64 has a valid node/output pair. The ELF lamp table has no names: `LAMP 0` through `LAMP 63` are synthesized by pinned PinMAME source and explicitly marked `pinmame_source_synthesized`, with `pinmame.label` aliases rather than `rom.label`. No semantic insert/GI/flasher assignment, fitted quantity, sharing, physical color or location is established. Each route remains availability unknown. All converter switches 0-95/101-132, canonical solenoids 1-33/45-48/51-72 and lamps 1-64 are represented; these legal envelopes are not physical inventories.

## Bounded runtime and display observations

`tfcp_1018.runtime.bounded` pins the successful 11-action fresh-state run, scenario, official harness, retained physical-mode wrapper, raw event trace and full external manifest. DLL SHA256 is `8044e4dfbcd66dd2d686075f2b942d8c60c4a04899c603d2d67a9b2ff6103cd5`. Mechanics and keyboard are disabled and no prior NVRAM is inherited. START 1 produces actual solenoid 4 states 127/0 and derived GAME ON 33 becomes 255. After explicit synthetic trough/shooter transfer, button 2 produces actual coil 2 states 255/44/0 plus virtual 47/48, and button 3 produces actual coil 3 states 255/44/0 plus virtual 45/46. Switch 6 produces coil 1, switch 7 produces coil 7, and switch 8 produces coil 6, each 255/0. These prove causal public routing under this scenario, not physical winding count or electromechanical timing.

The exact source declares one 16-character CORE_SEG16S line at index 0, segment_start 0, with four-bit segment modulation. Runtime reports type 13, length 16 at index 0 and delivers raw segment arrays. No decoded display text is claimed. The API also sends index 1 DMD-availability metadata, but no DMD frames are present; it is not asserted as an extra physical display. Stop reaches emulator state 0 and the wrapper exits 0. stderr nevertheless reports no NVRAM commit within 5000 ms; persistence is unverified.

An earlier fresh-state exploratory run retained as `runtime-tfcp-gameplay-01` passed the same initial routing checks but failed a drop-reset output-8 checkpoint after synthetic target assertions. It is diagnostic only. No successful drop reset, lock output 5, tilt, service menu, drain, complete game, physical ball travel or stable persistence is claimed. The successful bounded run uses separate new state and preserves this limitation.

## Physical recreation blockers and evidence acquisition

No own-edition wiring chart or full electrical manual is retained and no exact known-working home VPX was found in the ordered read-only user table roots or pinned script corpora. Own manufacturer prose confirms broad mechanisms but cannot settle electrical bindings or quantity. Candidate trough, lock and three-drop assemblies preserve firmware clues with explicit unresolved topology. Trough occupancy, jam behavior, launch path, reset policy, parts, connectors, NC construction, physical display assemblies, lamp semantics, quantities and all coordinates still require this edition's physical evidence. No commercial sibling hardware or geometry was copied. Normalized playfield coordinates remain x=0 left/x=1 right, y=0 rear/backglass/y=1 front/apron when evidence permits.

User input files were read without alteration. The official deterministic `tools/curate_spike1.py` regenerates the reviewed seed/knowledge and spatial blockers, with repeated --check and digest checks failing closed. Runtime callbacks settle routing only. Coverage stays partial with explicit missing physical input/output semantics, mechanism behavior/inventory, contact construction, variants, display fitment and spatial placement.
