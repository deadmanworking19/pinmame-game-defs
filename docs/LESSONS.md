the work you are about to do; do not read the whole file by default.

Each lesson ends with the archive lines that record the case behind it, in
`docs/archive/current-state-ledger-until-2026-10-01.md`, and with `verified:` where it was checked
against the repository code or pinned PinMAME source on 2026-10-01. The runbook wins where the two
disagree. Add a lesson here when it generalizes beyond one machine but matters only for a particular
task; a rule every session needs belongs in `docs/INSTRUCTIONS.md`. Keep each lesson to a few
sentences, in the section it applies to, and cite the commit or knowledge note that produced it.

## Finding and reading sources

- **Fetch IPDB through Wayback first.** IPDB answers plain HTTP and headless Chrome with 403. `https://web.archive.org/web/2024id_/<IPDB URL>` serves the archived bytes unmodified; cite the resolved capture URL and hash the file. Live, a headful Puppeteer session with a persistent `userDataDir` clears the challenge (also VPU, VPF). (archive L446, L677; verified: tools/curate_johnny_mnemonic.py cites full-timestamp `id_` URLs)
- **Cite the untouched download.** When a PDF needs decrypting or an OCR layer, the original stays the cited copy; the processed copy sits beside it for search only. (archive L272, L306, L425)
- **OCR finds pages; renders decide cells.** Acrobat exposes no scriptable OCR; `Windows.Media.Ocr` over native-resolution renders gives a usable search layer. An existing text layer can still be wrong: one shifted a parts list by a row, others scramble multi-column tables. Read every cited cell from the render. (archive L431, L447, L728)
- **Confirm the document is the machine.** A same-titled Internet Archive item can be the arcade video game. Render a page and check manufacturer and board part numbers before citing it. (archive L633)
- **Prove a page is missing before saying so.** Check that consecutive renders' printed folios increment by one; a scan can silently lack every even page. Derive the PDF-to-printed offset per section: rebound scans change it, bind sheets in reverse and duplicate pages. (archive L666, L900)
- **Read addenda, amendments and bulletins first.** They correct printed figures, part numbers and device identity (a printed relay amended to a coil). Give the correction its own source record, apply it, and keep the printed original in the device note. (archive L662, L900, L940)
- **Use a secondary chart only where it reproduces the primary.** It may fill a gap the retained manual leaves only when its overlapping columns match the primary schematic exactly and runtime evidence groups the circuits the same way. Disclose it on every affected device. (archive L677)

## Weighing sources and writing conflicts

- **Check every table against its siblings.** Expect typos, transposed rows and reversed Left/Right inside one manual; settle a misspelling from its symmetric partner. Prefer the parts list, assembly page or schematic over matrix-page labels: a matrix "(EOS)" can name a part the assembly page identifies as something else. (archive L638, L693, L897)
- **Copies of one table are one source.** Front-matter, section and schematic-side reprints neither corroborate each other nor stay aligned; they can drift by a row or split two against two. Decide with a different kind of page, or with the script. (archive L554, L622, L835, L122)
- **A blank or "Not Used" row is rebuttable.** It is evidence of non-fitment that a label on another page or an unreferenced driver `#define` does not overcome; a wiring page, a drawn location balloon or a live script binding does. (archive L693, L763, L767)
- **Settled disagreements are notes.** Two higher-authority sources that are independent of each other against one printed row settle it: follow them in structured data, keep the literal cell in the excerpt, and state the misprint on the device. A connector list that merely lacks an entry proves nothing. (archive L622, L692, L835, L1001, L122)
- **A resolution path must name evidence that exists.** Check every ROM short name against the record's own `drivers`; if no manual is retained, say so rather than cite a page. Also say what would not settle it, e.g. no harness trace shows which bulb a lamp-matrix bit reaches or which string plugs which connector. (archive L1066)
- **PinMAME source is emulator evidence, not fitment.** Per-game `core_set_pwm_output_type` typing is a brightness model; it can contradict printed bulbs and addresses and may be copied from a VPX table. A `*** PRELIMINARY ***` banner or an author's "no access to this game" header weakens that driver's mechanism tables and flipper fields. `hw.custSol` can be synthetic. (archive L406, L751, L752, L780, L846, L847, L879, L974; verified: capcom.c:751, cv.c `cv_getSol`, ft.c:181-185)
- **Trace a symbol's uses before judging it.** `#define` names and comments can be swapped or stale. Before calling a symbol unused, follow every use, including struct initializers handed to `mech_add`. A swapped name that the code uses consistently with the machine is a naming defect: a device note, not a conflict. (archive L662, L667; verified: tz.c:210-211, 601-624, mech.c:143)
- **Semantics are what the script's code does.** Sub and routine names can say the opposite of the objects they move; the object manipulation decides. (archive L406, L835)
- **A binding outside the platform's published range is dead code.** Check the address against what `core_getSol` and the driver can publish first: a BY35 table's `SolCallback(25..38)` never fires. (archive L917; verified: core.c `core_getSol`, by35.c:322,328)
- **Record a substitution, not hardware.** A table may write an unfitted address as a stand-in for real mechanism feedback; record the address as substituted and keep the real sensors as candidates. (archive L491)
- **Verification, not size, decides a table's authority.** An author's "not verified" header, a table nobody has launched, and a re-theme whose `cGameName` matches the ROM rather than the machine are leads. A thin or pre-1.0 build that is known to work keeps its runtime authority, but read what it omits as a gap, never as evidence: an empty light collection is not a missing lamp. (archive L167, L406, L734, L1136)
- **Retain the VPinMAME library the table loads.** Keep a machine-neutral copy of `core.vbs` and the platform library (`s11.vbs`, `de.vbs`, `de2.vbs`, `wpc.vbs`, `sega2.vbs`) and cite it by excerpt. The library, not the table, decides which addresses key handlers write; libraries differ, and a table constant can suppress a write. (archive L462, L466, L474, L306; verified: tools/pinmame_flipper_column.py)
- **Identify the lamp idiom before counting lamps.** Tables use `Lampz.MassAssign`, `vpmMapLights`, `SetLamp`, custom `ChangedLamps`/`NFadeL` loops or the shared `Lights()` array; a resolver for one returns a false-clean zero on another. Strip whole-line and trailing comments, count the controller's addresses, then explain every extra object. (archive L167, L236, L944, L964, L975, L999, L1011; verified: vpx_source.py `LAMP_PATTERNS` lacks `vpmMapLights`)

## Addresses, numbering and driver fields

- **Printed numbers are aliases.** A Self Test # column, a schematic's "column 9", a custom board's item numbers and printed flipper circuits are `manual.address` or `manual.self-test` aliases, never bindings. Run the ROM's own test where it displays each number as it fires. (archive L648, L668, L672, L690)
- **Derive public addresses from pinned core arithmetic.** Compute `CORE_CUSTSWNO` (on WPC the first custom column is public 121) and `CORE_CUSTSOLNO` (first is 51) in code, and triangulate with the script and a structural proof; a manual agreeing with a stale driver comment does not overrule that. Verify each table on a page separately: two can follow different rules. (archive L689, L703, L780, L847, L858; verified: core.h:302,330,335-347)
- **Compute masks and macros in code.** Map `invSw` through the driver's own `sw2m`, never by array position. Decode each file's own `INITGAME*` macro against `core_tGameData.hw` (`flippers, swCol, lampCol, custSol, soundBoard, display, gameSpecific1, ...`); BY35's fifth argument is `lampCol`, and System 11's `db` is `display`. (archive L762, L849, L894, L910; verified: core.c `core_setSw`, by35games.c:32-33, s11games.c:38-40, s11.h:220-226)
- **Re-read each game's own fields.** BY35 continuous outputs 17-20 and any extra strobe, System 11 `muxSol`, `gameSpecific1` and GI relays, Data East display arrays and `FLIP_SWNO` numbers differ per game; never copy a sibling's. Check whether the game has a GI channel at all. (archive L781, L803, L895, L911, L917, L996, L997; verified: by35.c:240-241, lisy35.c `lisy35_set_variant`)
- **Take the platform from the game's `GEN_*` value.** Use the root driver's game-data generation, not its machine-module symbol, an analogy or the brief: a module is shared across generations. (archive L163, L173, L185, L205, L685; verified: gen.h, stgames.c:229, tools/attach_pinmame_io.py)
- **A task brief is not evidence.** Count mechanism instances in the script and the sources; when the brief is wrong, record the correction rather than the brief's framing. (archive L726, L795, L838, L904, L921)

## Platform read paths and synthesized inputs

- **Fliptronic EOS is synthesized; buttons round-trip.** For each flipper a WPC driver declares with `FLIP_SOL`, `core_updateSw` rewrites the EOS bit (111/113, or 115/117) from the coil's `core_getSol` state after `CORE_FLIPSTROKETIME`; do not drive it, and do not infer physical EOS rest state from it. With keyboard handling off, buttons 112/114/116/118 round-trip; with it on, lower keys are copied into upper button bits lacking `FLIP_BUT`, so keyboard runs prove nothing about fitted upper buttons. (archive L116, L120, L606; verified: `core.c core_updateSw`)
- **System 11 reads the matrix uninverted.** `s11.c` hands the CPU `core_getSwCol` and `s11games.c` leaves `invSw` zero, so a switch the ROM treats as active at public 1 rests open. (archive L584; verified: `s11.c pia4a_r`, `s11games.c INITGAME`)
- **Capcom complements in `io_r`.** Outside the per-game `capInvSw` mask, public 1 is a closed contact; on Kingpin the mask is exactly the opto set. The Switch Test icon shows that level, not the expected rest. (archive L405, L409; verified: `capcom.c io_r`)

## Identity, variants and records

- **OPDB identity is gated by code.** `import-opdb [--check]` (`opdb.py`) rejects a resolved identity that disagrees with its OPDB record on title tokens (edition words count), year (more than one apart), manufacturer, an unlisted parenthetical qualifier, or the root description. It also rejects an override that lacks a reason, a cross-manufacturer override without an HTTPS `evidence_url`, and a redundant override. `promote_catalog_stubs.py --check-structure` rejects two resolved claimants of one ID. (archive L153, L197, L1080; verified)
- **Identity is still a curator's job.** Never apply `machines/opdb_id.csv` blindly; choose the physical edition's record through a reasoned override. If the snapshot lacks a record, leave `identity` missing. A record split off a production machine keeps that machine's ID only as a lead. (archive L159, L197, L288, L1082)
- **A clone can be another machine.** A driver on a different CPU board or controller generation is a separate record even when PinMAME declares it a clone; a board-swap conversion becomes `physical_conversion`. A shared short-name prefix proves nothing. Test that split drivers never rejoin. (archive L288, L508, L679, L697, L863)
- **`physical_compatibility`.** A different GEN constant, sound system or display layout makes a driver `compatible` (`identical` cannot carry `display_overrides`); firmware provenance alone does not, so a community ROM that changes only the music on unchanged hardware stays `identical`. Firmware that needs hardware the machine lacks makes it `different`. Shared init proves routing, not cabinet hardware, so a folded-in edition stays `unknown` until a source describes it. (archive L831, L840, L1036; verified: validation.py)
- **Years.** `machine.year` is the physical release year. A catalog year can be a firmware date and stays on that driver; a manual copyright can be a reprint. (archive L854, L934)

## Spatial placement

- **Callout limit.** Fit each drawing on validated placements. A table object matches its callout only if every read is within the fit's leave-one-out error and within 0.07 normalized; otherwise the placement stays `observed`. When outlying controls inflate leave-one-out, 0.07 alone decides. Projections are exempt. The 0.07 is a per-curator convention, so state it in the spatial report. (archive L270, L662; verified: curate_indianapolis_500.py, curate_twilight_zone.py)
- **A corroborating fit does not move the table's coordinate.** When a drawing fit checks table placements, a pass confirms count, side and order and the coordinate still comes from the table; a drawing supplies a coordinate only through the runbook's reproducible-measurement rule. A fit is visual reconciliation, not proof, since the table author may have traced the same manual. Leader-line counts give bulb quantity. (archive L118, L662, L898)
- **Frames and controls.** Give each page its own fit; never reuse another page's frame. Reject any control whose bounding box spans much of the table. Mark a placement outside the controls' extent as extrapolated and keep it `observed`. (archive L118, L450, L771)
- **Several tables.** Validate a position only when every retained factory-layout table agrees within 0.025 normalized, with each table's object chosen through its own script binding. A table derived from, or ancestral to, another retained table can only supplement. (archive L662, L1038; verified: lotr_spatial_resolve.py)
- **Mechanism projections.** Project a sensor inside a mechanism onto that mechanism's own object; the sensors of one rotating figure may share a coordinate. Children of a tilting group share a local coordinate, so use a playfield-fixed object at each one's spot instead. An emulator that derives a mechanism's switches from a position counter says nothing about the physical sensors: place fitted sensors from their own geometry when the table or a drawing provides it, and project onto the mechanism's fixed object only when no usable sensor geometry exists. (archive L640, L683, L695, L794)
- **Placeholders and helpers.** Look for placeholder rows (unplaced lamps lined up along an edge) and `is_visible=false` animation helpers. If same-named mechanism objects still disagree once the helpers are dropped, omit `spatial` rather than pick or average. (archive L651, L823, L827)
- **Picking the bulb.** Collapse render doubles to the member with `show_bulb_mesh`, then to the smallest falloff radius. Place a Flupper dome on its `FlasherbaseN`. A table's GI grouping is not the machine's wiring, so keep those placements `observed`, without a quantity. (archive L390, L594, L718)
- **Existence and placement are separate.** A `used` device may have no `spatial`, which keeps the record partial. A WPC-95 flasher wired to both a playfield bulb and an insert-panel bulb counts both in `quantity` but places only the playfield bulb. (archive L390, L763; verified: validation.py)
- **Out-of-range objects.** `extract_spatial_candidates` drops them silently, so check the raw extraction. Exclude a stray member when the device has other placements. Clamp a sole object to the edge, with its raw value disclosed, only when the manual puts the device at that edge. Omit `spatial` when the object lies off the playfield plane. (archive L606, L640, L683; verified: spatial.py)

## Excerpts

- **The size budget is a test.** `tests/test_excerpts.py` enforces it, and `make_excerpt.py --max-bytes` grants no exception. Only a page-scale drawing belongs in `PAGE_SCALE_DRAWINGS`; never list a table, crop it tighter. A listed ID that cites nothing, or now fits in 100 kB, fails too. (archive L1092; verified)
- **Fit, re-render, split.** `tools/fit_excerpt_images.py` shrinks over-budget table crops until they fit. `tools/rerender_excerpt_images.py` regenerates every crop from its recorded `image_derivation`. Split a dithered 1-bit matrix into quadrant crops. (archive L336, L1090; verified)
- **One image per excerpt.** When a transcription spans several pages, crop the one load-bearing page and name the others. Omit the image when no single page stands for the claim. (archive L1094; verified: schema)
- **Disclose normalization.** If the transcription normalizes separators, punctuation or footnote marks, say so in the excerpt. (archive L1214)

## Tests, curators and determinism

- **Prove each guard can fail.** Mutation-check every guard, or run it against the historical wrong wordings it exists to catch. A mis-escaped regex and a string broken by concatenation have both shipped as guards that could never fail. Assert identities, not counts. (archive L243, L264, L953, L1050)
- **Sibling-derived records.** When a record starts from a sibling's curator, assert that none of its artifacts names another machine's IDs or short names, or the sibling's game data, generation constant or table build. Build that forbidden set from `catalog/pinmame.json`; a hand-written blacklist only tests your memory. (archive L949; verified: test_lethal_weapon_3.py)
- **Script claims are tests.** Gate prose such as "the script never touches X" against a pinned address set. Scan for that set case-insensitively and recheck it against the script whenever evidence is present. The set is a lower bound: it can disprove an avoidance claim but never prove one. (archive L249, L953)
- **Recompute stated numbers.** Recompute every figure in an observation label from the raw runs, and every hard-coded coordinate from `gameitems`. (archive L306, L660)
- **Sidedness is checked everywhere.** `tests/test_spatial_sidedness.py` covers every record. Never swap observed coordinates to make it pass; a real inversion you keep needs a `KNOWN_INVERSIONS` entry. (archive L653, L804, L898; verified)
- **Reuse shared rules.** Tests read the shared constants rather than copying their values. Curators import `unresolved_conflicts` from `pinmame_game_defs.conflicts` rather than re-implementing it. (archive L1050, L1094; verified)
- **`--check` proves self-consistency only.** When a shared pass such as `import-opdb` adds fields to a record, add them to that record's curator too, or the next regeneration silently drops them. (archive L1096)
- **Manifests and timestamps.** Build manifests with `tools/build_external_evidence_manifest.py`, which sorts paths case-sensitively. Sorting `Path` objects is case-insensitive on Windows. Recompute a legacy case-insensitive manifest; never re-pin it. Take times from retained manifests, never from the clock. (archive L522, L1151; verified)
- **Pinned evidence is immutable.** Add new data in a successor file and pin both files. If a pinned run folder moves, keep its internal paths unchanged and disclose the move. (archive L660, L662)

## Harness and runtime evidence

- **Match the mechanics mask to the question.** `--handle-mechanics` defaults to 0, as LibPinMAME does. Bit N runs the driver's built-in `mech_add` slot N (slots 0-4); `hw.handleMech` runs whenever the mask is non-zero, tests its own bits, and can do more than move mechanism switches: copy cabinet inputs into the matrix (Johnny Mnemonic 116->67, 118->68) or time a custom solenoid (The Shadow's 51 needs bit 1). Use the known-working table's `Controller.HandleMechanics` for mechanism-feedback runs, use 0 for polarity probes on switches `handleMech` overwrites, and record which bit a channel needs before calling it live or dead. (archive L333, L394, L449, L662, L808, L842; verified: `run_pinmame_harness.py --handle-mechanics`, `core.c core_updateSw`, `mech.c mech_updateAll`, `jm.c`, `ts.c`)
- **Forced physical outputs are sampled once per poll.** Capcom and SAM force physical output, which LibPinMAME integrates only when a solenoid query such as `PinmameGetChangedSolenoids` runs; the runner now calls it every poll (about 10 ms), so shorter pulses can still be missed. Traces recorded before that call under-report solenoids: never read their negatives as absence. (archive L403; verified: `_poll_outputs`, `libpinmame.cpp`, `capcom.c`, `sam.c`)
- **Record the output mode.** Other drivers run in the default binary mode, where an auxiliary-board address can differ from physical mode: on the Whitestar double-magnet board, 35 is aux latch bit 2 in binary mode but the processor-reset strobe in physical mode, and 36 exists only in binary mode. (archive L317; verified: `se.c` 520-5143-00 branch)
- **Change one input per poll.** A response to two inputs changed together is unattributable: add one isolation run per input and a no-change control. If a modelled run seems to show a threshold, add a pair of runs that separates it from an edge rule. Word the result "consistent with", not "proven". (archive L318, L323, L583)
- **More polarity oracles.** Hold a home switch at each level from power-up and watch the motor search; hold a target bank at each level and count reset-coil retries; read a power-up troubleshooting list of switches whose level differs from the expected rest (Capcom C5 INFO; it covers only the switches it checks); hold every candidate during a stuck-switch search and let the ROM report each address (BY35). (archive L319, L409, L584, L859)
- **Decode ROM name tables across the driver family.** `tools/s11_rom_name_tables.py` and `tools/capcom_kingpin_rom_records.py` read the service text statically; pair each table with a runtime walk before binding addresses. A prototype ROM can name hardware that production prints UNUSED, and production firmware can still drive it. (archive L399, L582, L583)
- **Test order can place emitters.** The manual's lamp-test text (start lamp, step direction) plus the ROM's observed test order places lamps that no drawing numbers. (archive L552)
- **Pair displayed names with the address that changed.** Test-menu numbers are ROM selector numbers, not public addresses (`AUX #33` is not public 33), and a press count drifts from them after a skipped optional item. Navigate with the inputs PinMAME copies from, not the matrix addresses it overwrites, or presses double-register. (archive L404, L407, L1104)
- **Prove a `FLIP_SWNO` copy through the button bit.** A `pulse` hold rewrites its switch every poll and masks `core_updateSw`'s per-frame overwrite of the target; `set_switch` and `--initial-switch` write once. (archive L297, L407; verified: `_hold_switch`, `set_switch`)
- **Boot and service recipes.** Fresh WPC NVRAM stops on FACTORY SETTINGS RESTORED: WPC-95 cleared with Escape (5), World Cup Soccer with Begin Test (8) once and Escape three times. WPC-95 service buttons need the coin door open (22 released). A non-empty power-up report adds screens, so enable the mechanisms it checks and count menu presses from an exploratory run. System 11B: with -6 = 0, Advance twice (Game ID, Ad 70), set -6 = 1 and Advance once for Game-Over; set Auto Burn-in to YES with Credit, then -6 = 1 and Advance, for a coil test that names every step (tried on `GEN_S11B` only). BY35 ignores Self Test (-7) until the power-up test ends (about 18 s on Fathom). SAM needs `--ready-timeout` well above 10 s. (archive L395, L476, L496, L577-L581, L808, L912)
- **Check ROM bytes, not zip names.** A library zip can hold a differently built dump; compare member sizes and SHA-1 with the pinned driver before citing a run. (archive L492)
- **`import-legacy` is one-shot.** It rewrites every migrated machine and knowledge file from `games/*.json`, duplicating IDs over curated records, resetting coverage and stamping HEAD as the legacy revision. Some conflicts are written by a `*_spatial.py` curator; find what writes `definition["conflicts"]` first. (archive L1068, L1070; verified: `legacy.py import_legacy_definitions`)
